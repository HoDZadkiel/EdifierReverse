# 高音質（LDAC／LHDC）評估

評估日期：2026-10-27。範圍：ES850NB（耳機）、MP330（喇叭）在 Windows 上要用高音質編碼需要什麼條件。

## 結論

**限制主要在電腦端，不在耳機或我們的協定。電腦需要的是「編碼器」，不是解碼器，也不需要耳機的驅動。**

- 官方 App 的 LDAC／LHDC／高清編碼開關，只是告訴**裝置**允許或偏好哪種編碼。
- 實際用哪種編碼，是電腦（來源端）與裝置在藍牙 A2DP 連線時協商出來的。電腦端不提供某編碼，裝置端開得再多也用不上。
- 標準 Windows 沒有內建 LDAC，所以 LDAC 耳機在 Windows 上預設走的會是 SBC。

| 項目 | 需要嗎 | 說明 |
|------|--------|------|
| 解碼器 | 不用 | 解碼在耳機／喇叭裡 |
| 電腦端編碼器 | **需要** | 電腦要能把音訊編成該格式再送出 |
| 裝置的驅動 | 不用 | 走標準藍牙音訊 |
| 裝置端編碼開關 | 需要 | 即 ConneX 的開關，也是我們協定能讀寫的部分 |

## 官方 App 的線索

依據：反編譯碼（`CommandManager.java`、`CommandParser.java`、`HDAudioCodeActivity.java`）與字串資源 `resources.arsc`。

**指令**（見 [protocol-commands.md](protocol-commands.md)）

| 功能 | 查詢 | 設定 | 回應 |
|------|------|------|------|
| LDAC | `0x48` | `0x49`，payload `[值]` | `P[0]` |
| LHDC | `0x37` | `0x38`，payload `[值]`（另有 `[2, 值]` 的變體） | 長度 2 取 `P[1]`，否則取 `P[0]` |
| 高清編碼 | `0x91` | `0x92`，payload `[index, 值, 值2]` | `[index, ldac, lhdc]`；長度 2 且 index 為 7、10、13 時，`P[1]` 是 LHDC、沒有 LDAC |

- 官方 App 以「值 `>= 0`」決定是否顯示某編碼選項；回應裡缺少的位元組在官方解析中是 `-1`，代表**裝置沒有提供該選項**。
- 這些值各代表什麼（開／關、品質優先或連線優先等）**尚未解開**；App 把它們當作選項清單中的位置。

**官方提示文字**（英文版字串，逐字意思如下）
1. 「請確認你的手機支援 LDAC／LHDC 音訊編碼。」→ 證實來源端必須支援該編碼。
2. 「啟用此功能時，LDAC／LHDC 因藍牙頻寬限制而無法串流。」→ 有某個功能與高音質編碼互斥。是哪個功能我沒查到；**推測**可能是 ES850NB 的多點連線，未證實。
3. （中文字串）某功能需要先關閉高清音頻編解碼，**關閉後設備會重啟**。→ 切換高清編碼可能讓裝置重啟，不是無風險的開關。

## Windows 現況

- 依 [Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/5560825/bluetooth-codecs-supported-in-windows-11) 與相關指南：Windows 11 內建的 A2DP 編碼是 SBC、AAC、aptX；aptX Adaptive 只在 24H2 且搭配部分 Qualcomm 無線電時可用。**LDAC 不在內建清單**。
- 我沒有找到 2026 年 Windows 新增 LDAC 的公告。這是「沒找到」，不是「確定沒有」；以 Microsoft 官方的藍牙音訊文件為準。
- 依 [Wikipedia 的 LDAC 條目](https://en.wikipedia.org/wiki/LDAC_(codec))：在 Windows 上要用 LDAC，需要廠商提供的特殊驅動，或另外用支援 LDAC 的藍牙發射器。

## 兩款裝置

| | ES850NB | MP330 |
|---|---|---|
| 編碼（外部資料） | LDAC、SBC；LHDC 未出現；也沒看到 AAC | **查不到可靠資料** |
| 藍牙版本（外部資料） | 5.4 | 6.0 |
| 其他 | 多點連線；USB-C 有線模式會停用藍牙 | 24-bit／96 kHz Hi-Res 認證；有德文頁面標示不支援 aptX |
| 資料可信度 | 零售商規格表與 Edifier 文案，不是官方規格頁 | 零售商與評測頁。網路上的 LDAC 說法講的是另一個型號（M330 II），不能套用 |

- 來源：[PB Tech 的 ES850NB 頁面](https://www.pbtech.com/pacific/product/HSTEDI008500/Edifier-Evo-Space-ES850NB-Wireless-Over-Ear-Noise)；MP330 的資料來自零售商與評測頁，**未逐一核對**。
- 兩款**真正支援什麼，以實機 `0xD8` 的旗標為準**：位元組 18 的 bit1／bit2（LHDC／LDAC）、位元組 22 的 bit0（高清編碼），見 [protocol-d8.md](protocol-d8.md)。外部規格與旗標不一致時，以旗標為準並回頭修正本文件。
- 兩款走的傳輸不同（ES850NB 走 SPP、MP330 走 BLE，見 [findings.md](findings.md)）；這只影響控制通道，**音訊是另外走經典藍牙 A2DP**，與控制通道無關。

## 條件清單

| # | 條件 | 誰負責 | 目前狀態 | 怎麼確認 |
|---|------|--------|----------|----------|
| 1 | 裝置本身支援該編碼 | 裝置 | ES850NB：外部資料說有 LDAC；MP330：未知 | 實機 `0xD8` 旗標 |
| 2 | 裝置端已啟用該編碼 | 裝置（ConneX／我們的協定） | 未知 | 實機 `0x48`／`0x37`／`0x91` 回應 |
| 3 | 沒有與之互斥的功能 | 裝置 | 有互斥功能但不確定是哪個 | 實機觀察；官方提示文字 |
| 4 | 電腦端能送出該編碼 | **電腦** | 標準 Windows：**LDAC 不行** | 見下一節 |
| 5 | 連線品質足夠 | 環境 | 未知 | LDAC 位元率高，官方文字提到頻寬限制 |

條件 4 是目前的瓶頸，而且**不是本專案能解的**。

## 讓電腦端有 LDAC 的路線

這些是我的整理，**我沒有查證具體產品或驅動，也沒有實測**。

| 路線 | 做法 | 優點 | 注意 |
|------|------|------|------|
| 外接藍牙發射器 | 用支援 LDAC 的 USB 藍牙發射器；它在電腦上是 USB 音效卡，編碼由它自己做 | 不需改 Windows，不依賴驅動 | 需要額外硬體；要確認發射器本身支援 LDAC，並且要與耳機配對（耳機不再和電腦直接配對） |
| 廠商驅動 | 依 Wikipedia 的說法，需要廠商提供的特殊驅動 | 不需額外硬體 | 取決於電腦的藍牙晶片是否有這類驅動；我沒有找到通用做法 |
| 有線（僅 ES850NB） | USB-C 有線模式 | 不經藍牙編碼 | 外部資料說有線模式會停用藍牙；這也正是官方 TempoHub 的使用情境（見 [findings.md](findings.md)），與你要用藍牙的目標不符 |

不建議自行安裝來路不明的第三方藍牙驅動或音訊修改工具：它們會替換系統藍牙堆疊，風險與效果都無法在這裡評估。

## 本專案能做與不能做

**能做**
- 讀取裝置端的編碼狀態與支援旗標（`probe` 已加入 `0x48`／`0x37`／`0x91` 三個只讀查詢）。
- 之後在確認安全的前提下，切換裝置端的編碼設定。

**不能做**
- 讓電腦多出一種編碼。這屬於 Windows 藍牙堆疊或外接硬體的範圍。
- 保證開啟裝置端 LDAC 就會聽到 LDAC。

**風險**
- 切換高清編碼可能讓裝置重啟（官方提示文字）。因此 `probe` 白名單只有查詢，設定類指令（`0x49`、`0x38`、`0x92`）被測試明確排除在外。
- 值的意義未解，不要憑猜測寫入。

## 實機要抓的資料

在另一台電腦跑 `probe`（步驟見 [handoff-other-pc.md](handoff-other-pc.md)），重點看：

| 要看什麼 | 來源 | 用途 |
|----------|------|------|
| LDAC／LHDC／高清編碼旗標 | `0xD8` 回應位元組 18、22 | 裝置到底支不支援（條件 1） |
| LDAC 設定值 | `0x48` 回應 | 裝置端目前狀態（條件 2） |
| LHDC 設定值 | `0x37` 回應 | 同上；ES850NB 若沒有 LHDC，可能無回應 |
| 高清編碼 `index`／`ldac`／`lhdc` | `0x91` 回應 | 裝置端提供哪些編碼選項（`-1` 代表沒有） |

判讀提示：
- `0x37` 無回應，或 `0x91` 的 `lhdc` 為 `-1`：該裝置沒有 LHDC，符合 ES850NB 外部資料的預期。
- `0xD8` 位元組 18 的 bit2 為 1：裝置宣告支援 LDAC。
- 兩款若在同一台電腦測，請記下電腦的藍牙晶片／介面卡型號，後續評估電腦端驅動時會用到。
